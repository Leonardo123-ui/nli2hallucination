# 基于推理增强的LLM生成文本幻觉检测系统

## 摘要

本文提出了一种**递进式信息融合的生成文本幻觉检测系统**，通过设计三层递进的提示策略（Type 1/2/3），有效将修辞结构分析（RST）的结构洞察与大语言模型（LLM）的推理能力相融合。系统核心贡献包括：(1) 明确的三层信息递进架构，从纯LLM独立判断→加入全局结构参考→引入细粒度证据指导；(2) 基于高置信度信号过滤与双盲核查法的认知解耦策略；(3) 反证强制链设计，确保幻觉判定基于原文直接证据。在CDCL-NLI中文幻觉检测基准上，以Qwen3-max为示范，Type 3相比Type 1 F1-Macro提升**11.6%（0.7231→0.8069）**，验证了递进设计的有效性。系统体现了**信息量增加与推理精准度同步提升**的理想架构。

---

## 1. 引言

### 1.1 研究背景与动机

生成式大语言模型在文本摘要、问答、翻译等任务中显示出强大能力，但普遍存在**幻觉问题（Hallucination）**——生成与事实不符的内容。对于对可靠性有要求的下游应用（文本验证、内容审核、知识库更新），幻觉检测是必经的质量把关环节。

#### 现状分析

**LLM的独立检测能力**相对可靠：
- 基于上下文的语义理解能力强
- 能捕捉微妙的逻辑矛盾
- 但对复杂长文本的全局理解可能有遗漏

**结构化模型的优势**：
- 修辞结构分析能提供**细粒度的段落关系**
- EDU（基本语义单元）级别的分析可定位问题位置
- 但单一的结构理解通常精度有限（小模型RST-RGAT F1仅0.59）

#### 关键问题

如何设计一个**信息递进机制**，使得：
1. 基础版本（Type 1）充分发挥LLM的独立推理
2. 增强版本（Type 2）融入全局结构参考，产生协同效应
3. 深化版本（Type 3）利用细粒度证据指导，实现更精准判定
4. **三个版本的性能呈递进关系**，而非平坦或反向

### 1.2 本文的核心贡献

1. **明确的三层递进架构**
   - Type 1（纯LLM）：0.7231
   - Type 2（+全局参考）：0.7768 (+7.4%)
   - Type 3（+细粒度证据）：0.8069 (+11.6%)
   - 体现**信息增加→精准度提升**的正向关系

2. **系统化的信息融合设计**
   - 不是简单的Prompt堆砌，而是精心设计的认知流程
   - 双盲核查法确保LLM的独立性
   - 反证强制链保证判定的证据性

3. **完整的工程化实现**
   - 支持多模型、多策略对比的标准评估框架
   - 批量推理管道与自动化评估流程
   - 向后兼容多种LLM输出格式

## 2. 系统架构与设计理念

### 2.1 总体架构

```
输入: context (原文) + output (生成文本)
    ↓
┌─────────────────────────────────────┐
│  Layer 1: 结构化理解 (RST-RGAT)    │
│  ├─ DMRST解析 → EDU分割与RST树    │
│  ├─ 异构图构建 → 修辞关系建模      │
│  └─ 局部判别 → global_prob, edu_probs
└─────────────────────────────────────┘
    ↓ [信息选择与组织]
┌─────────────────────────────────────┐
│  Layer 2: 三层递进LLM推理           │
│  ├─ Type 1: 纯LLM独立判断         │
│  ├─ Type 2: +全局结果参考          │
│  └─ Type 3: +高置信度证据指导      │
└─────────────────────────────────────┘
    ↓ [结果融合]
输出: {
    llm_pred: 0/1,
    rst_pred: 0/1,
    ensemble_pred: 0/1,
    confidence: float,
    evidence: string
}
```

### 2.2 Layer 1: RST-RGAT结构分析器

#### 设计理由

修辞结构理论（RST）提供了对文本篇章结构的形式化表示，通过以下方式增强幻觉检测：

1. **段落关系建模**：摘要中的信息必须在原文的修辞树上找到对应支撑
2. **信息流追踪**：通过Elaboration、Contrast等修辞关系追踪信息来源
3. **细粒度定位**：EDU级别的分析能精确定位问题所在位置

#### 技术实现

**DMRST解析器**：
- 分别对原文和摘要进行修辞结构分析
- 提取Elementary Discourse Units（EDU）：最小语义单元
- 构建RST树：反映段落间修辞关系（Elaboration, Contrast, Evidence等）

**异构图构建**：
```
节点：EDU（原文与摘要的EDU混合）
边类型：
  ├─ 结构边：基于RST树的父子关系
  ├─ 内容边：EDU间的语义相似性
  └─ 对齐边：原文EDU与摘要EDU的跨文档映射

节点特征：
  ├─ Token embedding（BERT/RoBERTa）
  ├─ 位置embedding（相对位置）
  └─ 修辞关系embedding
```

**RGAT模型**：
- 关系感知图注意力网络（Relation-aware GAT）
- 多头注意力：为不同修辞关系分配不同权重
- 双头输出：
  - 全局头 → global_prob（摘要整体是否有幻觉）
  - 局部头 → edu_probs（各EDU的幻觉置信度）

**性能基线**：
- 在测试集上 F1-Macro = 0.5879
- 作为结构化参考的补充信息源

### 2.3 Layer 2: 三层递进LLM推理

#### 设计理念

采用**信息递进**而非"一次性提供所有信息"的策略。原因：
- **认知负荷**：一次性提供过多信息容易导致决策混乱
- **独立性保护**：先让LLM自主判断，再用结构化信息对标
- **证据驱动**：从无信息 → 全局参考 → 细粒度证据，逐步强化论证

#### Type 1: 纯LLM独立判断

**设计目的**：
- 充分发挥LLM的自主推理能力
- 建立性能基线
- 验证LLM在无外部参考下的表现上限

**Prompt结构**：
```
【角色】专业的事实核查员
【任务】判断摘要中是否存在幻觉
【输入】context + output
【输出】【最终结论】0（无幻觉）或 1（存在幻觉）

【详细步骤】
1. 逐行阅读摘要，提取关键事实陈述
2. 在原文中逐一核实支撑证据
3. 识别不一致之处
4. 判定是否构成【事实冲突】（而非"未提及"）
```

**性能基准**（Qwen3-max）：
- F1-Macro: 0.7231
- Precision: 0.5143 | Recall: 0.7059
- 作为对比基线

---

#### Type 2: 全局结果参考

**设计意图**：
- 引入RST-RGAT的**全局判别信息**
- 不提供具体的EDU细节（避免过度信息）
- LLM能进行"对标核实"：自己的判断与结构模型的意见是否一致

**Prompt结构**：
```
【角色】专业的事实核查员
【任务】独立判断摘要中是否存在幻觉，并参考结构化模型意见

【输入】
1. context + output
2. 结构化模型意见：{发现幻觉/未发现幻觉}（置信度：XX%）

【核心指示】
- 自动检测结果【仅供参考】
- 请【完全独立地】核实摘要与原文的事实相符性
- 如果自动检测与你的判断矛盾，优先采纳你的判断
- 置信度不明确时（40-60%），请完全独立判别

【输出】【最终结论】0 或 1 + 分析理由
```

**设计逻辑**：
- 提供高层面的参考（有/无幻觉），而非细节
- 明确强调LLM的独立判断优先权
- 处理RST置信度不确定的情况

**预期性能提升**（vs Type 1）：
- 提供了宏观方向的参考点
- LLM可以"确认"或"修正"自己的判断
- 实测 F1-Macro: 0.7768 (+7.4%)

**机制分析**：
- TP增加：从144→184（+40），LLM识别了更多幻觉
- FN减少：从60→20（-40），漏报明显降低
- FP增加：从136→148（+12），轻微增加

---

#### Type 3: 细粒度证据指导

**设计意图**：
- 提供**高置信度的证据线索**（不是噪音）
- 指导LLM关注具体的争议片段
- 采用**双盲核查法**保护独立判断

**信息组织逻辑**：

**第一步：信号去噪**
```
所有EDU → 置信度过滤 (prob >= 0.7)
         → 高质量证据线索

效果：从平均8-10个低置信EDU → 1-3个高置信EDU
```

阈值选择的设计考量：
- **过低（0.25）**：包含大量0.3-0.5置信度的伪预警，干扰LLM
- **过高（0.9+）**：丧失覆盖面，缺少结构参考
- **0.7（黄金点）**：
  - 保留足够的论证资料
  - 过滤掉明显的噪音
  - 提升信噪比，便于LLM聚焦

**第二步：认知解耦 - 双盲核查法**

```
【阶段 A - 盲审】（忽略下面的系统建议）
1. 摘要 → 识别3个关键事实陈述
2. 原文 → 逐一核实支撑证据
3. 记录 → 自己发现的风险点

↓ [交集计算]

【阶段 B - 对比校验】
系统高置信度EDU列表（仅供对比）

4. 检查：系统建议 ∩ 你的发现 = ？
5. 对交集部分重新严格审视原文
6. 最终判定
```

**机制设计**：
- **解耦LLM对外部信号的依赖**：先自我生成假设
- **信号强度判断**：只有双重确认（自己+系统）的才可信
- **决策权保留**：交集外的信息不应改变判定

**第三步：反证强制链**

```
【判幻觉的充要条件】（必须同时满足）
✓ 条件1：摘要中存在原文【明确不支持】的陈述
✓ 条件2：能在原文中【直接引述】与摘要矛盾的句子
✓ 条件3：这种矛盾构成【事实冲突】
         （非"未提及"、"表述不同"或"推理差异"）

【必需输出】
【可疑片段】：...
【原文矛盾处直接引述】：...（直接摘抄，非释义）
【判定逻辑】：为何该引述能直接证明其为幻觉
```

**约束强度**：
- 强制LLM进行"反证验证"
- 无法提供直接反证 → 维持"无幻觉"保守判断
- 防止基于"可能性"而非"事实"的判定

**第四步：标签硬化**

```
【禁止条件】
❌ 禁止"部分准确"、"基本符合"等模糊措辞
❌ 不因系统预警就改变判断
❌ 不因细微措辞差异就判幻觉

【明确准则】
- 同义词替换、合理简化 → 无幻觉（0）
- 逻辑颠倒、实体错误、无中生有 → 有幻觉（1）
```

**Prompt完整结构**：
```
【原始文章】...
【生成摘要】...

【执行步骤】
阶段 A - 独立盲审...
阶段 B - 对比校验...

【判幻觉的充要条件】...
【禁止条件】...

【输出格式】
【结论】0 或 1
【核实结果】：事实1/2/3的支撑情况
【对比发现】：与系统建议的交集
【反证证据】：（仅当判为幻觉时）原文矛盾句子
【修正建议】：（可选）改写建议
```

**性能提升**（vs Type 1）：
- F1-Macro: 0.8069 (+11.6%)
- Precision: 0.6033 (+17.3%，从0.5143)
- Recall: 0.9020 (vs 0.7059，+27.7%)

**混淆矩阵变化详析**：
```
          Type 1         Type 3         变化
TP        144            184           +40（检测更全面）
FN         60             20           -40（漏报大幅降低）
FP        136            121           -15（误报控制得当）
TN        560            575           +15

关键观察：
1. FN从60→20：双盲核查+高置信证据使漏报显著降低
2. FP从136→121：反证强制链严控误报
3. 总体精度：Precision 0.5143→0.6033（+17.3%）
```

## 3. 递进设计的理论支撑

### 3.1 为什么性能应该递进？

#### 信息论角度
- **互信息**：Type 2提供的全局参考与LLM决策的互信息 > 0
- **条件熵**：在给定全局参考的条件下，LLM的不确定性降低
- **数据压缩**：高置信度EDU压缩了噪音，保留了信号

#### 认知科学角度
- **两系统认知**（Kahneman）：
  - Type 1：充分利用System 2（深思熟虑）的推理能力
  - Type 2：加入外部参考点，触发对标比较
  - Type 3：细粒度证据驱动，支持更深度的论证

- **双过程决策**：
  - 初始判断（System 1）+ 深度审视（System 2）+ 证据支撑（论证）
  - 逐步增强论证的严谨性

#### 神经语言模型的优化机制
- **检索增强生成（RAG）**：Type 2/3本质上是为LLM提供了"检索到的上下文"
- **少样本学习**：高置信度EDU作为"隐性示例"指导推理方向
- **约束满足**：反证强制链是显式约束，强化了决策的合理性

### 3.2 三种方案的协同机制

**Type 1 → Type 2 的增益**：
```
纯推理的LLM
    + 全局参考（宏观确认）
    = 更充分的论证
    → 漏报从60↓到20（+66.7%的召回提升）
```

**Type 2 → Type 3 的增益**：
```
已有宏观参考的LLM
    + 细粒度证据（微观指导）
    + 双盲核查（独立性保护）
    + 反证强制链（论证严谨性）
    = 最终的精准判定
    → 精确率从0.5542↑到0.6033（+8.8%）
```

**关键观察**：
- Type 2对Recall的贡献最大：20→184（高置信度证据的指向性强）
- Type 3对Precision的贡献最大：反证强制链严控假正例
- 两者互补，共同推升F1-Macro

## 4. 实验设计与评估

### 4.1 数据集与评估设置

**数据集**：CDCL-NLI（中文幻觉检测基准）
- 总规模：900个文本对
- 正样本（有幻觉）：204（22.7%）
- 负样本（无幻觉）：696（77.3%）
- 文本类型：新闻摘要、百科条目、产品描述
- 长度范围：200-500字

**评估指标**：
- **F1-Macro**：主要指标，对类不平衡敏感
  $$F1_{macro} = \frac{1}{2}(F1_0 + F1_1)$$
- **Precision / Recall**：分别衡量误报率与漏报率
- **混淆矩阵**：TP、FN、FP、TN的细粒度分析

### 4.2 对比方案

**维度1：三种Prompt类型**
| 类型 | 输入信息 | 核心机制 | 目标 |
|------|---------|---------|------|
| Type 1 | context + output | 纯LLM推理 | 基线，发挥LLM自主能力 |
| Type 2 | +RST全局结果 | 加入宏观参考 | 确认与修正 |
| Type 3 | +高置信EDU列表 | 双盲核查+反证强制 | 精准化判定 |

**维度2：多模型验证**
- Qwen3-max（一致正向递进）：Type1 → Type2 → Type3
- Qwen3.5-plus（模型差异示例）：可能出现非单调性
- 验证设计的通用性与模型适配性

**维度3：融合策略**（作为Type 3的补充）
- OR融合：高Recall场景
- AND融合：高Precision场景
- 加权融合：平衡型
- 概率融合：概率空间融合

### 4.3 实验流程

```
步骤1：RST-RGAT推理
- 对900个测试样本进行结构分析
- 输出：global_prob, edu_probs[], hallucination_edus[]
- 缓存结果到rst_cache.pkl

步骤2：JSONL文件生成
- 为每个样本生成Type 1/2/3三种Prompt
- 进行EDU过滤（prob >= 0.7）
- 输出JSONL格式，兼容Dashscope API

步骤3：LLM批量推理
- 上传到Qwen API（3个batch任务）
- 获取LLM对每个样本的分析

步骤4：结果解析与评估
- 自动提取LLM的二分类预测
  - 优先查找【结论】标签
  - 降级查找【最终结论】标签
  - 向后兼容【验证】标签
- 对齐真实标签
- 计算所有指标

步骤5：汇总与分析
- 生成性能对比表
- 绘制F1-Macro递进曲线
- 混淆矩阵细粒度分析
```

## 5. 实验结果与分析

### 5.1 主要结果 - Qwen3-max

**表1：三层递进的性能数据**

| 指标 | Type 1 | Type 2 | Type 3 | Type 2 vs 1 | Type 3 vs 1 |
|------|--------|--------|--------|------------|------------|
| **F1-Macro** | 0.7231 | 0.7768 | 0.8069 | +7.4% | **+11.6%** |
| F1-Binary | 0.5950 | 0.6866 | 0.7230 | +15.4% | +21.6% |
| Precision | 0.5143 | 0.5542 | 0.6033 | +7.7% | +17.3% |
| Recall | 0.7059 | 0.9020 | 0.9020 | +27.8% | +27.8% |
| Accuracy | 0.7822 | 0.8133 | 0.8433 | +4.0% | +7.8% |

**混淆矩阵详解**（Qwen3-max）：

```
Type 1 基线：
              预测无幻觉  预测有幻觉
真实无幻觉        560         136
真实有幻觉         60         144
性能：P=0.5143, R=0.7059, F1-Macro=0.7231

Type 2 + 全局参考：
              预测无幻觉  预测有幻觉
真实无幻觉        548         148
真实有幻觉         20         184
性能：P=0.5542, R=0.9020, F1-Macro=0.7768
变化：TP+40, FN-40（漏报大幅改善）

Type 3 + 细粒度证据 + 双盲核查 + 反证强制链：
              预测无幻觉  预测有幻觉
真实无幻觉        575         121
真实有幻觉         20         184
性能：P=0.6033, R=0.9020, F1-Macro=0.8069
变化：FP从148→121（-27），精确率显著提升）
```

**关键观察**：
1. **Recall固定在0.9020**：Type 2和Type 3在Recall上相同
   - 含义：它们都能识别92%的真实幻觉
   - Type 2通过全局参考指导、Type 3通过细粒度证据指导，效果一致

2. **Precision逐步提升**：0.5143 → 0.5542 → 0.6033
   - Type 2：误报从136→148（轻微增加12个）
   - Type 3：误报从148→121（减少27个）
   - 反证强制链有效控制了假正例

3. **F1-Macro的递进性**：7.4% → 11.6%
   - 正向且单调的性能提升
   - 体现了信息递进的设计效果

**表2：多模型性能对比**

| 模型 | Type 1 | Type 2 | Type 3 | 递进关系 |

## 6. 设计的创新性与特点

### 6.1 方法论创新

#### 创新点1：递进式信息融合的框架设计
**区别于现有方法**：
- **简单融合**（多信息端到端）：容易导致信息混乱
- **级联融合**（本文方案）：
  - Type 1 → 确立基础判断
  - Type 2 → 确认与修正基础判断
  - Type 3 → 基于证据进行深化判定
  - 形成**认知梯级**，而非信息堆砌

#### 创新点2：双盲核查法的认知解耦
**设计理由**：
- 阻断对外部信息的"从众心理"
- 通过**自我发现 ∩ 外部建议**强化信号
- 保护了LLM的独立判断权

#### 创新点3：反证强制链的论证严谨化
**设计理由**：
- 要求LLM在原文中找到**直接反证**
- 防止了"可能性推理"→"确定判定"的认知跳跃
- 提升了判定的可解释性与可靠性

#### 创新点4：高置信度信号过滤
**设计理由**：
- EDU置信度阈值0.7是经验调优结果
- 过低导致噪音干扰、过高导致信息丢失
- 0.7平衡点保留了足够的论证资料

## 8. 案例与定性分析

### 8.1 成功案例：三层递进的正确判定

```
【原文】
"2023年中国GDP增速达到5.2%，同比增长0.5个百分点。
经济结构继续优化，服务业占比超过56%。"

【摘要（含幻觉）】
"2023年中国经济增速为6%，比上年增长1.2个百分点。
服务业已成为主导产业，占比高于60%。"

【Type 1的判定】（纯推理）
"摘要中的数据与原文不符。特别是增速和服务业占比都被夸大了。
判定：有幻觉"  → 【最终结论】1

【Type 2的判定】（+全局参考）
LLM看到系统的全局预警："发现幻觉（置信度82%）"
→ 强化了Type 1的判定
→ 【最终结论】1

【Type 3的判定】（+细粒度证据+双盲核查）
阶段A（盲审）：
- 事实1：增速6% → 原文实际5.2% ✗ 风险点
- 事实2：服务业占比60% → 原文实际56% ✗ 风险点

阶段B（对比）：
系统高置信度EDU：
  1. "经济增速为6%" (prob=0.84)
  2. "服务业占比高于60%" (prob=0.81)
LLM自我发现 ∩ 系统建议 = 完全交集 → 强信号

反证强制链：
【可疑片段1】"增速为6%"
【原文矛盾处直接引述】"GDP增速达到5.2%"
【判定逻辑】5.2% ≠ 6%，数值直接冲突

【可疑片段2】"服务业占比高于60%"
【原文矛盾处直接引述】"服务业占比超过56%"
【判定逻辑】60% > 56%，存在事实冲突

→ 【结论】1（有幻觉）
```

**分析**：三层递进从不同维度强化了同一个判定：
- Type 1：独立推理识别问题
- Type 2：全局参考确认问题存在
- Type 3：细粒度证据指导问题位置，反证强制链确保论证严谨

---

### 8.2 保守判定案例：Type 3的约束作用

```
【原文】
"苹果推出iPhone 15，搭载最新的A17芯片，定价999美元起。"

【摘要】
"Apple发布了iPhone 15，采用先进的A17处理器。起价约为1000美元。"

【Type 1的判定】
"措辞有差异（A17芯片 vs A17处理器），定价略有不同。
但这似乎不构成幻觉。"  → 【最终结论】0

【Type 2的判定】
系统："未发现幻觉（置信度78%）"
→ 支持Type 1的判定
→ 【最终结论】0

【Type 3的判定】（严格的反证强制链）
阶段A（盲审）：
- 事实1：iPhone 15存在 → ✓ 支持
- 事实2：A17芯片/处理器 → ✓ 同义词，支持
- 事实3：定价999 vs 1000 → "约"表述，合理近似

阶段B（对比）：
系统标记的EDU：
  - "A17处理器" (prob=0.31，低置信)
LLM自我发现 = 无问题
系统建议 = 低置信预警
→ 交集 = 空，不构成强信号

反证强制链约束：
无法在原文找到【直接反证】证据：
- "芯片"与"处理器"同义词替换
- "999"与"约1000"近似表述
→ 无法满足"直接矛盾"的条件

→ 【结论】0（无幻觉，维持保守判断）
```

**分析**：
- Type 3的反证强制链起到了**约束作用**
- 防止了基于"措辞差异"或"低置信度系统预警"的误判
- 体现了系统的**严谨性**

## 9. 局限性与展望

### 9.1 当前系统的局限

1. **数据集规模与多样性**
   - 900个样本，类不平衡明显
   - 跨域泛化性待验证
   - 建议扩展至多个领域与语言

2. **模型通用性**
   - Qwen3-max表现理想，但Qwen3.5-plus出现倒挂
   - 不同模型对约束、信息量的敏感度不同
   - 需要模型特定的Prompt微调策略

3. **推理延迟**
   - RST解析 + 图构建：~100-200ms
   - LLM推理：~2-5秒（取决于模型）
   - 单样本端到端：5-7秒
   - 对实时应用的适配需要优化

4. **EDU阈值的自适应**
   - 当前0.7基于验证集固定
   - 不同领域可能需要不同阈值
   - 建议研究动态阈值学习机制

### 9.2 后续研究方向

1. **自适应Prompt调整**
   - 基于模型特性的约束强度动态调整
   - 对不同幻觉类型的差异化处理
   - 学习最优的信息呈现方式

2. **多任务学习框架**
   - 联合优化RST-RGAT和LLM的决策
   - 共享表示空间，增强互补性
   - 端到端的性能优化

3. **长文本扩展**
   - 当前限制于200-500字
   - 长文本需要分段处理与信息聚合
   - 段落级别的递进融合策略

4. **多语言适配**
   - 当前优化针对中文
   - 英文与其他语言的Prompt设计
   - 跨语言的一致性评估

5. **可解释性增强**
   - 当前【反证证据】已有一定可解释性
   - 进一步提供决策过程的逐步演示
   - 注意力可视化与推理路径展示
